# Deploy esy free on Render

Genuinely $0, no account-verification wall. One Docker web service (the
[Dockerfile](../Dockerfile)) builds the React SPA, bundles it into the Spring
Boot jar, and serves **both** the SPA and `/api` on one HTTPS URL — so the
frontend's relative `/api` calls work with no CORS.

## Free-plan caveats

- The instance **sleeps after ~15 min idle**; the next request cold-starts (~30–60s).
- DB is **in-memory H2** (Render's free plan has no persistent disk), so data
  resets on restart/redeploy. `DataInitializer` reseeds products; dev-login
  still works every run. Fine for a demo; not for real orders.

## Deploy (one time, ~5 min of your input)

The repo is already on GitHub (`OtoGvazava/esy`) with [render.yaml](../render.yaml).

1. Sign up at **https://render.com** (GitHub login is easiest — no card for free).
2. **New + → Blueprint**.
3. Connect/select the **`OtoGvazava/esy`** repo. Render reads `render.yaml`
   and shows one service `esy` (Docker, Free).
4. **Apply** / **Create**. First build takes ~5–8 min (Node + Maven in Docker).
5. Open the service URL: `https://esy.onrender.com` (or the name Render assigns).

`JWT_SECRET` is auto-generated by Render (`generateValue: true`). Nothing else
to configure.

## Verify

- Storefront loads products (MacBook Pro / AirPods Pro — the seeded "main" tenant).
- Sign in: globe/account → email `admin@esy.shop` → Verify → shop-owner; or
  Gmail/iCloud buttons. Admin product CRUD works.
- Deep links (e.g. `/product/5`, `/cart`) load directly (SPA fallback).

## Gmail (Google OAuth) sign-in

The code is fully wired (server-side Google OAuth2 → JWT → SPA). It only needs
a Google OAuth client — **you** create this; I can't make accounts or hold the
secret. "Continue with Gmail" stays inert until these env vars are set.

1. **Google Cloud Console** (https://console.cloud.google.com) → create/select a
   project → **APIs & Services → OAuth consent screen**: External, app name
   `esy`, your support email; scopes `openid`, `email`, `profile`. While it's in
   *Testing*, add your Google account under **Test users** (or Publish the app).
2. **Credentials → Create credentials → OAuth client ID → Web application**.
   **Authorized redirect URIs** (exact, both):
   - `https://<YOUR-RENDER-HOST>/login/oauth2/code/google`
   - `http://localhost:8080/login/oauth2/code/google`  (local dev)
   (No "Authorized JavaScript origins" needed — it's a server-side flow.)
3. Copy the **Client ID** and **Client secret**.
4. **Render** → your service → **Environment** → add:
   - `GOOGLE_CLIENT_ID` = …
   - `GOOGLE_CLIENT_SECRET` = …
   Leave `APP_OAUTH2_REDIRECT_BASE` unset (same-origin). Save → it redeploys.
5. **Local dev**: run the backend with
   `GOOGLE_CLIENT_ID=… GOOGLE_CLIENT_SECRET=… APP_OAUTH2_REDIRECT_BASE=http://localhost:5173`
   plus `npm run dev` for the web. "Continue with Gmail" → Google → back signed in.

Notes: the JWT, cookie-based OAuth state (works under stateless sessions), and
`{baseUrl}` redirect resolution behind Render's TLS proxy are all handled in
code and verified. iCloud stays a dev stand-in (Apple OAuth not configured).

## Redeploy

`autoDeploy: true` — every push to `main` rebuilds and redeploys automatically.

## If you later want persistence

Upgrade the Render service to a paid instance + add a Render PostgreSQL, then
set `SPRING_DATASOURCE_URL` / `SPRING_DATASOURCE_USERNAME` /
`SPRING_DATASOURCE_PASSWORD` and `JPA_DDL_AUTO=update` env vars on the service
(the backend already reads them — see `application.yml`).
